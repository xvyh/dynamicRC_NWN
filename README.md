# Dynamic Reservoir Computing via Neuromorphic Nanowire Networks
This repository include all code needed to simulate the neuromorphic nanowire network, and using it for time series forecasting via reservoir computing, for the manuscripts "*Learning Chaotic Dynamics with Neuromorphic Network Dynamics*" (https://arxiv.org/abs/2506.10773)", and "*Dynamic Reservoir Computing with Physical Neuromorphic Networks*" (https://arxiv.org/abs/2505.16813).

## Requirements
Python 3.8.2 is needed. 
All required external Python packages are in [`requirements.txt`](requirements.txt). 

Only NumPy is strictly needed for simulations. 
Matplotlib is only for figure making, and tqdm is a quality-of-life addition which can be easily ignored by overwriting the progress bar object with an identity map (i.e. `pbar = lambda *args, **kwargs: args[0]`). 

## Navigation
[`neurowiresim.py`](neurowiresim.py): Simulation of the neuromorphic nanowire network.

[`neuropred.py`](neuropred.py): Autonomous time series prediction via reservoir computing. Uses the neuromorphic network as the reservoir, but can be easily adapted for any other reservoir.

[`example_usage.py`](example_usage.py): Example usage.

[`requirements.txt`](requirements.txt): Dependencies. Use `pip install -r requirements.txt` to install.

[`networks/`](networks): The adjacency matrices of two neuromorphic networks used in the manuscripts. 
These networks are generated by simulating the self-assembly of physical nanowire networks - see this [repo](https://github.com/aloe8475/PhysicalReinforcementLearning/blob/main/generate_networks/wires.py) for generating custom networks. 

## Usage

To simulate a neuromorphic nanowire network, only the [`neurowiresim.py`](neurowiresim.py) file is needed. First create a `NanowireNetwork` object. 
All physical parameters have default values, only the adjacency matrix needs to be specified. 
For the supplied 500-nanowire 9905-edge network, 
the simplest `NanowireNetwork` object would be the following.
```python 
with open("networks/500nw_9905jns.npy", 'rb') as f:
    adj_mtx = np.load(f)
neuro_params = {'adjmtx':adj_mtx}
nwn = NanowireNetwork(**neuro_params)
```
Then specify the list of electrode indices, array of input signals, timestep size, and how many timesteps of simulation (often same as input signal length), to obtain all network readouts $r$. 
```python
r = neuro_sim(nwn, electrode_indices, input_signal, dt, steps=input_signal.shape[0])
``` 

Use [`neuropred.py`](neuropred.py) for autonomous time series prediction via reservoir computing. An example run would look like the following (same as example in [`example_usage.py`](example_usage.py))
```python
sdata = run(
        input_signal    = 0,
        t_warmup        = 100,
        t_train         = 27000,
        t_pred          = 29000,
        input_electrodes= 'random',
        output_electrodes='other',
        drain_electrodes= [336],
        n_input         = 24,
        n_readout       = 475,
        n_total         = 500,
        alpha           = 0.2,
        neuro_params    = {'adjmtx':adj_mtx},
        exp_index       = 0,
        return_flux     = False,
        dynamic_meas    = False,
        nonlin_meas     = False
        )
```
Most of the above variables are self explainable and details can be found in the docstring. The parameter `alpha` is same as $\alpha$ in the manuscript (in units of volts) and is a global input signal scaling parameter. 
Input node locations can be specified by `input_electrodes` as a list of node IDs (integers), or as string `"random"` to randomly generate input electrodes. 

The experiment index `exp_index` also determines the seed for the random generation of input nodes, input weights and bias entries. 
If `input_signal` is an integer (instead of an array of input values), it generates the Lorenz signal as input, with `input_signal` integer as the initialisation ID.  

To change neuromorphic network connectivity, change `adj_mtx` in `neuro_params`. 
To generate a square lattic network, see `square_lattice_network` function; to specify certain nodes on this lattice as input nodes, see `sqlattice_convert_to_id` to convert node coordinates to node index IDs. 



The following data (and dictionary keys) are saved in the dictionary object `sdata`, and can be used for figure making. Access with `val=sdata["key"]`: 

| key           | description |
| ---           | ----------- |
|`id`           |experiment ID, also the RNG seed for generating input nodes, $W_{\rm in}$ and $b_{\rm in}$|
|`ic_id`        |initial condition ID for generating the input Lorenz signal|
|`readouts`     |readout signals from the readout nodes during training|
|`W`            |the trained output matrix $W$|
|`pred_readouts`|predicted readouts signals during autonomous prediction|
|`yhat`         |predicted teacher signal $\hat{y}$ |
|`nonlin`       |average nonlinearity measure|
|`nonlin_loc`   |edge-wise (location respecting) nonlinearity measure|
|`dynam`        |the edge-wise dynamic measures |
## Reproducibility
Chaotic time series are very sensitive to initial conditions.
Hence to preserve reproducibility of results, the hardware, software, number of CPUs and RAM usage must all be kept the same. 
Slight differences in any of the above will lead to different numerical results from those in the manuscript, but the statistics and overall conclusions will remain the same. 

The Intel Xeon E5-2470 v2 CPU was used for the simulations conducted for this paper, provided by the Artemis high performance computing resource at the [Sydney Informatics Hub](https://www.sydney.edu.au/research/facilities/sydney-informatics-hub/digital-research-infrastructure.html), University of Sydney.

The available code were made for usage with Python 3.8.2.
Three CPUs were used for multiprocessing for all simulations. 
For the 2000 node network, 80GB of RAM is needed for reproducibility (while saving all simulation outputs, hence the large RAM usage; only 2GB is needed for standard usage).
For the 500 node network, 20GB of RAM is needed for reproducibility (only 1GB needed for standard usage).
